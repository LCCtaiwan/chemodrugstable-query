## 第一輪缺漏原因及修正

第一輪使用 TFDA 37（未註銷資料），無法解釋大量歷史藥證。本輪改用官方 TFDA 36，保留註銷狀態，但搜尋適應症及仿單入口仍僅使用未註銷資料。

- 42,890 筆依 NHI 官方連結 licId 與 TFDA 通關識別碼串接。新增支援通關 S 前綴及 R 流水號，R 不可刪除或當成數字。
- 1,887 筆因通關欄位空白，依同一官方來源觀察到的「中文藥證類別 → 識別碼類別」轉換，再核對完整流水號。這是由來源資料推得的編碼正規化，不是另有官方交叉對照表。只有類別編碼唯一、且至少有兩個不同流水號的佐證才啟用；逐筆輸出 licenseMethod 可區分此方法。
- 非空但不一致的通關欄位不以推導覆蓋；多個候選不自動連結；未知編碼不從健保碼或品名猜測。
- 402 筆未確認明細見 unresolved.json；357 筆包括缺少完整藥證類別的識別碼與特殊品項碼，未推斷其藥證。45 筆無法在本次識別碼索引找到資料，不能直接稱為無藥證。

來源 SHA-256 見 summary.json；保留第一輪報告供比較。原始下載檔與逐筆 CSV 不提交 Git。

來源：[健保 CSV](https://info.nhi.gov.tw/api/iode0000s01/Dataset?rId=A21030000I-E41001-001)、[TFDA 36](https://data.fda.gov.tw/data/opendata/export/36/json)。

## 重現及驗證

```sh
python tools/nhi/audit_license_links.py --csv /path/nhi.csv --tfda-licenses /path/tfda36.zip --as-of 2026-09-14 --output /path/audit
python -m unittest discover -s tests -p 'test_nhi*.py'
```

26 個 Python 測試通過，包括來源網域、流水號不一致、R 字母保留、S 前綴、空白通關編碼回補、類別衝突、已註銷及一對多不自動連結。
